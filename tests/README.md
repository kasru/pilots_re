# tests

Скрипты проверки. Проект не имеет тестов, линтера и CI — **единственная верификация это сборка
и запуск игры с чтением debug-лога** (`AGENTS.md`). Эти скрипты автоматизируют именно это.

## windows/

Запуск через PowerShell 7 (в `PATH` его нет, `pwsh` на машине — это PS 5.1, без тернарного
оператора и с BOM при `Set-Content -Encoding utf8`):

```
& "$env:ProgramFiles\PowerShell\7\pwsh.exe" -NoProfile -File tests\windows\pfuzz.ps1
```

| Скрипт | Что делает |
|---|---|
| `buildall.ps1` | Собирает все 4 конфигурации подряд, печатает только SUCCESS/FAILED |
| `x86check.ps1` | Собирает x86 debug **последним** (чтобы `SDL2.dll` была x86), гоняет 12 с, сверяет маркеры `auxMainLoop=1` / `GameMainLoop=2` и отсутствие исключений |
| `pfuzz.ps1` | Основной харнесс: стартует x64 debug, входит в сцену 1, сыплет кликами `PostMessage` по сетке + клавиатура, скриншоты, поиск `EXCEPTION: 0xC000` |
| `fuzz.ps1`, `nav.ps1` | Более ранние версии того же навигационного прогона (оставлены как референс) |
| `play.ps1` | «Человеческий» прогон: клик → выдержка 4 с, чтобы анимации и диалоги успевали отыграться |
| `realfuzz.ps1` | То же, но реальным вводом мыши (`SetCursorPos`+`mouse_event`) |
| `relfuzz.ps1` | Прогон release-сборки (без `DBG_LOG`) — конфигурация, в которой пало у пользователя |
| `probe.ps1` | Сборка x64 debug + `pfuzz` одной командой |
| `check_x64_file.bat` | Пофайловая компиляция MSVC x64: показывает предупреждения о несовпадении указателей (это и есть сигнал миграции LP64) |
| `analyze_probe*.ps1` | Разбор логов компиляции: гистограмма `C4xxx`, фильтр «указательного» класса предупреждений |
| `pwsh_test.ps1` | Проверка окружения: версия pwsh, тернарник, `UIntPtr`, UTF-8 без BOM, P/Invoke, DPI |

### Как кликать в игру

Координаты — **логические** (клиент 640×480). Рабочий приём: `PostMessage(hwnd, 0x0200, 0, LP)`
→ `0x0201` с `wParam=1` → `0x0202` с `wParam=0`, где `LP(x,y) = ((uint)y<<16)|((uint)x&0xFFFF)`.

`PostMessage` предпочтительнее реального ввода: он адресует сообщение прямо в окно игры, не требует
фокуса и не двигает курсор. Реальный ввод (`mouse_event`) уходит в то окно, что под курсором, а
Windows не даёт фоновому процессу увести фокус — отсюда «клики мимо».

Проверять доставку надо по самой игре: `SdlGameWndProc: msg=0x201 wp=0x1 lp=0x1C0002A` — это
ровно `(42,448)`.

`SetCursorPos` требует **физических** координат = логические × 1.25 (процесс DPI-aware, игра — нет).

## linux/

Запуск обычным `sh`. Скрипты больше не привязаны к `/home/ntadmin/...` — переходят в корень
репозитория через `cd "$(dirname "$0")/../.."`.

| Скрипт | Что делает |
|---|---|
| `test_wm_freeze.sh` | Регрессия_WM: клиент обязан оставаться 640×480 через любой цикл maximize/restore/fullscreen/iconify; залипание 0×0 после restore замораживает рендер |
| `diag_hang.sh` | Тест завершения: SIGUSR1 → штатный выход; если через 10 с жив, ловим SIGSEGV, чтобы обработчик игры напечатал бэктрейс залипшей точки |
| `diag_video.sh` | Смоук-тест видео: интро+старт через ffmpeg-MCI, потом чистый выход |
| `x11ctl.py` | X11/EWMH-драйвер через ctypes+libX11 — заменяет xdotool/wmctrl; нужен первым двум скриптам |

## Рабочий процесс

1. `buildall.ps1` — все 4 конфигурации собираются.
2. `x86check.ps1` — 32-бит не изменился (байт-в-байт тот же код).
3. `pfuzz.ps1` — 64-бит живой, 0 исключений.
4. Пересобрать x64 последним, иначе `SDL2.dll` останется x86 и `PILOT_RV_x64.EXE` не стартует.

Надо помнить: **release-сборки пишут `DBG_LOG` в пустоту.** Падение воспроизводить только на
debug-сборке — иначе в логе не окажется ни исключения, ни дампа регистров.
