# Братья Пилоты: По следам полосатого слона — порт на современные платформы

Порт приключенческой игры **«Братья Пилоты: По следам полосатого слона»** (Gamos и Студия
«Пилот», издатель 1C, 1997) на Windows, Linux, Nintendo Switch и macOS.

Это не эмулятор. Исполняемый файл игры `PILOTS.EXE` восстановлен в исходный код на C17 по
полностью разобранной базе IDA Hex-Rays: каждая функция переписана байт-в-байт, вместе с
особенностями оригинала. Собранный заново движок читает те же данные игры — они дописаны в хвост
оригинального `PILOTS.EXE` — и исполняет те же байт-код-скрипты: логики конкретной игры в C-коде
нет, только проигрыватель.

> [!NOTE]
> Нужна своя копия игры: файл `PILOTS.EXE` и папка `MOVIES` — в репозитории их нет, как и любых
> ресурсов игры — фильмов, графики, звука.

## Поддерживаемые платформы

| Платформа | Файл | Примечание |
|---|---|---|
| Windows x86 | `PILOTS_RE.EXE` | основная сборка |
| Windows x64 | `PILOTS_RE_x64.EXE` | рядом с x86, каждый со своим `SDL2.dll` |
| Linux i386 | `PILOTS_RE` | собирается в контейнере `pilots-build` |
| Linux x86_64 | `PILOTS_RE_x64` | |
| Nintendo Switch | `PILOTS_RE.nro` | |
| macOS Intel, 10.13–10.14 | `PILOTS_RE` | i386, самодостаточный exe |

> [!NOTE]
> 32-разрядная сборка — не прихоть: движок хранит адреса в 32-битном `int` (так было в оригинале),
> поэтому вся его память обязана лежать ниже 2 ГБ. На Windows и Linux это решается принудительно,
> на Switch — отображением по низкому адресу, а XNU 64-битному процессу такую память не выдаёт
> (проверено: hint игнорируется, `MAP_FIXED` и `mach_vm_allocate` отвечают отказом). Отсюда потолок
> macOS — i386: 10.15+ и Apple Silicon 32-битные программы не запускают вообще.

> [!TIP]
> Готовые сборки — на странице
> **[kasru.github.io/pilots-installer](https://kasru.github.io/pilots-installer/)**: она берёт
> бинарники из релизов этого репозитория и складывает архив с вашей копией игры прямо в браузере —
> образ диска никуда не отправляется.

## Как запустить

1. Соберите порт (см. «[Сборка](#сборка)») или возьмите готовую сборку для своей платформы.
2. Положите исполняемый файл **рядом с оригинальным `PILOTS.EXE`** — данные движок ищет не в
   текущем каталоге, а рядом со своим образом.
3. Запустите. Сохранения (`PILOTS*.SAV`, `PILOTS0.230`) совместимы с оригиналом, включая перенос
   между 32- и 64-разрядными сборками.

Каталог игры выглядит так:

```text
PILOTS/
  PILOTS.EXE        оригинал: данные игры дописаны в хвост файла
  PILOTS_RE.EXE     эта сборка
  MOVIES/           фильмы (INTRO.AVI, START.AVI, FINAL.AVI)
  PILOTS1.SAV       сохранения (совместимы с оригиналом)
  ...
```

На Nintendo Switch каталог с данными — `sdmc:/switch/pilots/` (в нём же `PILOTS.EXE`); запуск — из
hbmenu, командной строки на консоли нет.

На Linux скачанному файлу нужно вернуть право на запуск — `chmod +x PILOTS_RE_x64`.

## Управление

### Клавиатура и мышь (Windows, Linux)

| Ввод | Действие |
|---|---|
| `Alt`+`Enter` | включить/выключить полноэкранный режим |
| `-` (минус) | растянуть картинку на весь экран ↔ сохранить пропорции 4:3; из обычного окна первое нажатие сразу включает полный экран с растяжением |
| `Ctrl` (удерживать) | белые кружки над объектами, с которыми игра принимает щелчки |
| Левая кнопка мыши | основное действие |
| Правая кнопка мыши | второе действие |
| `Space`, `Enter` | пропустить идущий фильм |
| Щелчок по фильму | пропустить идущий фильм |
| Стрелки и клавиши действия | задаёт сама игра (до восьми направлений и четыре особые клавиши) |

### Геймпад (Nintendo Switch, Windows, Linux)

| Кнопка | Действие |
|---|---|
| Левый стик | курсор |
| `A` | щелчок левой кнопкой мыши |
| `B` | щелчок правой кнопкой мыши |
| `-` (View у Xbox, Share у PlayStation) | тот же переключатель картинки, что клавиша `-` |
| `R` (удерживать; `RB` у Xbox/PlayStation) | подсветка объектов, как `Ctrl` |
| `X`, `Y`, `L` (`LB`) | не назначены |

> [!NOTE]
> SDL приводит раскладки разных геймпадов к единому виду: `A` — нижняя кнопка, `B` — правая, как у
> Xbox. Геймпад можно подключить и отключить во время игры.

## Ключи запуска

| Ключ | Действие |
|---|---|
| `-fullscreen` | запуститься сразу в полноэкранном режиме |
| `-datapath <каталог>` | взять данные игры из указанного каталога |
| `-log [файл]` | записывать журнал работы: с именем файла — в него, без имени — в `<имя exe>_debug.log` |
| `-version` | показать описание и версию и выйти (окно на Windows, строка в stdout на остальных) |

> [!NOTE]
> В release-сборке журнала по умолчанию нет вообще — ни файла, ни строк; включает его только ключ
> `-log`. Относительный путь файла считается от каталога запуска, а не от каталога с данными
> (`-log` разбирается раньше, чем `-datapath` успевает сменить рабочий каталог), и в этом каталоге
> файл создаётся сразу при старте. В debug-сборке журнал пишется всегда, `-log` там лишь меняет
> файл. Дамп регистров и стека при падении остаётся только у debug-сборки — с `-log` в release
> журнал просто обрывается на последней строке.

## Настройки

| Переменная окружения | Значение | По умолчанию |
|---|---|---|
| `PILOTS_SHARE_AUDIO` | `0` — отдельные звуковые устройства для музыки и звука фильма, `1` — одно общее | `0` на Windows, `1` на остальных |
| `PILOTS_LOAD_QUIET_MS` | сколько миллисекунд экран должен стоять при чтении данных, чтобы показать индикатор загрузки (50–60000) | `1000` |

## Что изменено по сравнению с оригиналом

Поведение игры повторяет оригинал, включая его особенности (в коде они отмечены комментариями
«Особенность оригинала»). Менялось только то, что мешало играть:

- игра запускается на современных Windows (32- и 64-разрядных), Linux и Nintendo Switch, а на
  macOS — на Intel с 10.13/10.14; оригинальный `PILOTS.EXE` там не работает;
- глубоко лежащий каталог игры больше не приводит к сбою — длинные пути обрабатываются корректно;
- окно всегда имеет полную клиентскую область 640×480;
- кнопки «звуки» и «музыка» в панели настроек регулируют громкость независимо: выключение
  звуковых эффектов больше не глушит музыку;
- щелчок, остановивший идущий фильм, не срабатывает на элемент игры, лежащий под ним.

Порт также добавляет возможности, которых в оригинале не было:

- полноэкранный режим с сохранением пропорций картинки (`Alt`+`Enter`);
- переключение «растянуть на весь экран» ↔ «сохранить пропорции 4:3» одной кнопкой на всех
  платформах: клавиша `-` или кнопка `-`/View/Share на геймпаде;
- подсветка всех объектов, с которыми игра принимает щелчки (`Ctrl` или `R` на геймпаде);
- заметный индикатор загрузки сцены вместо «зависшего» экрана;
- выбор каталога с данными игры ключом `-datapath`;
- журнал работы по требованию ключом `-log [файл]`: в release он выключен по умолчанию, в debug
  пишется всегда;
- управление геймпадом: на Nintendo Switch — консольным, на Windows и Linux — любым, который
  понимает SDL (Xbox, PlayStation, Nintendo Pro Controller и совместимые).

## Как это работает

- **Движок, а не эмулятор.** `PILOTS.EXE` декомпилирован (IDA Hex-Rays) и переписан на C17
  байт-в-байт; оригинальный машинный код не исполняется. Логика игры — байт-код-скрипты из файла
  данных; C-код — интерпретатор: 56 кодов команд, 57 встроенных функций, правила классов, тайлы,
  спрайты, звук и фильмы.
- **Адреса — 32-битные.** Оригинал хранит указатели в `int`, и порт сохраняет это соглашение, а не
  переписывает движок. Поэтому вся память держится ниже 2 ГБ: на Windows x64 образ прибит
  `/BASE:0x10000000 /DYNAMICBASE:NO`, а пул выдаётся через `VirtualAlloc`; на Linux работает
  `MAP_32BIT`; на Switch блок отображается по названному низкому адресу через transfer-memory;
  на macOS это невозможно (см. примечание о платформах), поэтому там i386.
- **Вывод.** Движок рисует в собственный 8-разрядный кадровый буфер 640×480 со списком грязных
  прямоугольников; порт выкладывает его в SDL2-текстуру. В полноэкранном режиме картинка
  масштабируется с сохранением пропорций и центрируется.
- **Звук.** 8-разрядный моно PCM 11025 Гц из оригинального микшера уходит в очередь SDL. Музыка —
  MIDI: на Windows через `midiOut`, на остальных платформах — через libADLMIDI (эмуляция OPL3).
- **Фильмы.** Собственный формат движка читается им же; AVI на Windows играет MCI, на остальных
  платформах — ffmpeg, со звуком через общий микшер.
- **Ввод.** На Windows SDL2 подклассирует окно и передаёт игре настоящие сообщения Win32
  (`WM_MOUSEMOVE`, `WM_LBUTTONDOWN`, …); на остальных платформах события SDL переводятся в те же
  сообщения — обработчики оригинала работают без изменений. Геймпад нормализуется через
  SDL_GameController и превращается в те же сообщения мыши.

## Сборка

| Платформа | Команда | Результат |
|---|---|---|
| Windows x86/x64 | `SRC\build-vs2022.bat [debug\|release] [x86\|x64]` | `SRC\out\<arch>\PILOTS_RE[_x64].EXE` |
| Windows, CMake | `cmake -S . -B build-win64 -A x64` → `cmake --build build-win64 --config Release` | `build-win64\Release\` |
| Linux i386 | `cmake -S . -B build32 -DPILOTS_M32=ON` (в контейнере `pilots-build`) | `build32/PILOTS_RE` |
| Linux x86_64 | `cmake -S . -B build64` | `build64/PILOTS_RE_x64` |
| Linux x86_64, самодостаточный | `sh scripts/build_linux_static_podman.sh` | `build-static/PILOTS_RE_x64` |
| Nintendo Switch | `sh scripts/build_switch_podman.sh debug` | `build-switch-dbg/PILOTS_RE.nro` |
| macOS i386 | `cmake -S . -B build-mac32 -DCMAKE_OSX_ARCHITECTURES=i386 -DCMAKE_OSX_SYSROOT=/ -DPILOTS_STATIC_SDL2=ON` | `build-mac32/PILOTS_RE` |
| Релиз (архивы) | `pwsh scripts\make_release_archives.ps1 -Dist <каталог> -Out <куда>` | `pilots-re_<версия>_<платформа>.zip/.tar.gz` |

Собранные бинарники складываются в каталоги по платформам (`x64/`, `x86/`, `linux/`, `linux386/`,
`mac/`, `switch/`) и одной командой превращаются в архивы релиза: версия в именах берётся из
`SRC/version.h`, в каждый архив идут `README.md` и `LICENSE`, а `.zip` создаётся без сжатия —
такой читает браузер установщика без inflate.

Обычная Linux-сборка использует системные SDL2 и ffmpeg. Самодостаточная (`build-static`, она же
лежит в релизе) вшивает их в один файл: скачанный `PILOTS_RE_x64` запускается на любом десктопном
дистрибутиве, где есть X11 или Wayland, без `libSDL2-2.0.so.0` и `libav*`. Динамическими остаются
glibc и графика/звук, которые SDL2 загружает во время работы, — статическая glibc этого не умеет.
Сборка идёт в контейнере `Containerfile.static`, где ffmpeg собран из исходников минимальным
набором (AVI, MS RLE, Cinepak, rawvideo; LGPL-2.1+): брать `libavcodec.a` из дистрибутива нельзя —
там включены все декодеры, и статическая линковка тянет их все вместе с GPL-кодеками. Оттуда же
берётся и SDL2 — не из дистрибутива, а собранный из исходников на базе `debian:bullseye`
(glibc 2.31): бинарник может работать только там, где glibc не старше той, с которой он собран, а
дистрибутивные архивы SDL2 и ffmpeg собраны против свежей. На bookworm получался порог 2.36
(`arc4random` в `libSDL2.a` и переверсионированный `hypot` в `libavutil`) — это отсекало Ubuntu 22.04
и Debian 11. Сейчас порог — **glibc 2.31, то есть Debian 11 и Ubuntu 20.04 или новее**.

Windows-сборке нужны Visual Studio 2022 (MSVC) и Windows SDK, Linux и Switch — CMake, SDL2 и
libavcodec (для Switch — devkitA64/libnx из devkitPro), macOS — SDL2, собранный под i386, и ffmpeg
(пути к ним передаются через `CMAKE_PREFIX_PATH`); порядок сборки macOS с патчем SDL2 описан в
`patches/README.md`. Инструменты и флаги подробно разобраны в `AGENTS.md`.

> [!CAUTION]
> Собранный файл нельзя называть `PILOTS.EXE`: движок открывает данные как `.\PILOTS.EXE`
> относительно своего каталога и прочитал бы собственный образ вместо данных игры.
